PR #46 審查（opus）找出三項設計層級問題，2026-08-03 由使用者本人當場拍板解決（不再留到之後的 G1 才決定）：

  • outline 靜態邊框與 focus-visible 焦點環共用同一視覺：實際以真實鍵盤 Tab 導覽並截圖核對（非臆測）後，外層 48px 命中區 wrapper 的焦點框（瀏覽器預設矩形／略帶圓角）與內層 40px pill 自己的邊框在視覺上是兩個可分辨的獨立形狀（矩形外框＋膠囊內框，並非同一圈重疊到分不出來），予以維持、不修改。component.tag.border-focus 的命名與數值皆維持現狀，理由：其色值 #598ae8 就是 SVG 本身畫的 outline 描邊顏色，不可為了改名而連帶質疑數值；命名雖與 Text input／Textarea 的「僅 focus 時出現」語意不同，但與 component.button.border-focus／component.icon-button.border-focus（同樣是「恆常顯示的 outline 靜態邊框」，且 Button 這組命名已通過實際 G1 審查）完全一致，只改 Tag 一個反而製造新的不一致，故維持整個 batch1 家族現有命名慣例。
  • disabled 元素類型：改為 <span class="tag tag--disabled" aria-disabled="true">，不再用 <button disabled>，與其餘五個純狀態變體（皆為 <span>）一致——disabled 沒有從 SVG 或規格文字得出的獨立互動語意，規格明文「純狀態 tag 不可點擊」，用 <button> 只是誤套用了本檔案既有的原生 disabled 驗證慣例，並非這個變體本身需要的語意。verify.mjs 已改用 aria-disabled 屬性驗證。PR #46 第三輪複審（opus）另外指出：改成 <span> 後雖然滿足規格「不可互動、移除焦點與點擊」的要求，但停用態與 neutral 的視覺差異只有背景色與文字透明度，兩者都是顏色，違反規格「不得只依顏色傳達停用」「不以顏色單獨表達語意，需要文字、圖示或上下文共同說明」的既有條文（此問題原本就存在，並非本次改動造成的視覺退步；但 <button disabled> 至少會被輔助科技播報，改成不可聚焦的 <span> 後這條路徑實質消失，是本輪造成的程式化傳達退步）。已補上 <span class="visually-hidden">（已停用）</span>，用文字滿足規格要求，不影響任何像素——這不是發明 SVG 未畫出的視覺，純粹是螢幕閱讀器可讀、肉眼不可見的文字。
  • removable 移除鈕圖示位置：新增 component.tag.remove-icon-offset（23px，逐一核對 c-badge-tag SVG 的 tag-removable X 圖示中心與 rect 右緣量測值 144－121＝23px），並讓 removable 變體自己的 padding-inline-end 改用 calc(remove-icon-offset − remove-control-size ÷ 2)（23－16＝7px）取代共用的 16px，讓圖示中心恢復到與 SVG 一致的 23px，同時完整保留 32px 命中區，不犧牲無障礙需求。verify.mjs 已新增真實 getBoundingClientRect 量測斷言（23px），不只信任 CSS 宣告值。

  • 狀態圖示實際只有 24.5px，非宣稱的 28px：圖示 SVG 的 viewBox="0 0 32 32"（32 個單位是為了同時容納較寬的 danger 三角形）被壓縮進一個依 icon-size（28px）決定寬高的 CSS 容器，導致 viewBox 內每個單位、包含 circle 的 28 個單位，全部一起被等比縮小成 24.5px。已新增 component.inline-alert.icon-render-margin（2px，純實作用的縮放安全邊界，非 SVG 量測值）：圖示 SVG 容器改為 icon-size + icon-render-margin × 2（32px），讓 viewBox 的 32 個單位與渲染像素維持 1:1，圖示水平位置的 calc() 也一併扣掉這個邊界，確保視覺中心不變。verify.mjs 新增對 <circle> 元素本身（而非外層 SVG 容器）的真實 getBoundingClientRect 量測斷言，不再只信任容器尺寸。
  • 關閉鈕位置偏移 24px、X 圖示只有 8px 寬（來源是 12px）：容器原本無條件套用 padding-inline-end: 24px（給沒有關閉鈕的變體留白），疊加在關閉鈕自己 48px 寬置中的效果之上，導致圖示中心距卡片右緣變成 48px，而非來源 SVG 實測的 24px（translate(712 24)，X 圖示本地座標 18,18 至 30,30 換算後的中心距）——與 PR #46 當初 Badge/Tag 移除鈕圖示位移是同一種錯誤形狀（命中區疊加在既有內距之上，而非取代它）。已新增 .inline-alert:has(.inline-alert__dismiss) 規則將該變體的 padding-inline-end 歸零（24px 期望位移剛好等於 48px 按鈕寬度的一半，歸零後按鈕貼齊卡片右緣即可自然置中對到 24px），並將 X 圖示路徑從 8 個單位改畫成 12 個單位，與來源尺寸一致。verify.mjs 新增對兩個 <path> 的真實 getBoundingClientRect 量測斷言（圖示寬度、距右緣距離），不再只信任 CSS 宣告值。
  • 兩個未被消費的 focus token：component.inline-alert.border-width／border-focus 先前只在 :root 宣告，沒有任何 .inline-alert* CSS 規則實際引用——關閉鈕的 focus ring 其實完全由既有跨元件的全域 :focus-visible 規則滿足規格文字「2 px blue focus ring」的要求，這兩個 token 是重複而非缺口，已直接移除（tokens／CSS／verify.mjs 三處同步），不做成沒有消費者的裝飾性宣告。
