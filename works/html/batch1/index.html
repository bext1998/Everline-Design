PILOT CANDIDATE · AWAITING G1

本輪範圍、token 缺口與刻意未實作項目

依 issue #17 建議，本輪只試做 Button、Checkbox、Text input／Textarea 三群（15 群中的 3 群），完成後停在人類審查閘門（G1），不繼續其餘 12 群。

P0 token 完整性核對發現並已最小補上的 4 個缺口（詳見 tokens/everline-draft.tokens.json 各欄位 $description，皆為新增、未改動任何既有解析值）：

  • component.button.foreground-neutral — neutral／outline 變體的文字色其實是 off-white，不是既有 foreground（white）token 所指的顏色；來源 SVG 只有 primary／danger 兩個變體的文字有 fill="#fff" 覆寫。
  • component.checkbox.border／border-width — 未勾選狀態的 1px #444 描邊（border-default）先前未被任何 checkbox token 涵蓋。
  • component.text-input.foreground-disabled — Text input 自己的 SVG 群組從未畫出 disabled 狀態，此值沿用 batch 3 Number input 欄位已審查通過的 disabled 處理方式（背景維持實色、前景以 color-mix() 混合），非新視覺決定。
  • component.textarea.foreground／placeholder／border-width-focus／border-focus — Textarea 先前完全沒有這些 token，儘管 SVG 已經畫出 placeholder 文字（foreground／placeholder 直接依 SVG 實測值補上），focus 邊框則沿用 Text input／Search field／Number input 已建立的同一套技法。

刻意未實作、留給 G1 決定的項目（依 AGENTS.md：SVG 未畫出的視覺不得自行發明）：

  • Button 的 pressed、loading 狀態——沒有任何已核准的視覺依據，本批完全不實作。
  • Button outline 變體與 focus ring 共用同一組 2px 藍色描邊視覺，這是 docs/design-system-v0.1-draft.md 已記錄的既有未決問題，本批未解決：outline 按鈕本身已有 2px 藍色描邊，鍵盤 focus 時會在外側再疊加一圈 outline，兩者在 outline 變體上會同時可見、視覺上更接近雙圈而非單一語意，是否需要獨立的 focus 表現方式（例如外擴光暈）留待人類審查決定，不在本輪擅自結案。
  • Text input／Textarea 的 error 狀態——需要新的語意色決策，本批不實作；readonly 僅做原生語意支援（游標與可否編輯），沒有專屬視覺語言。
  • Checkbox 的 focused／error group——focus 沿用既有全域 :focus-visible 技法（非新視覺決定），error group 因涉及多選欄位層級的產品決策，本批不實作。
  • Button／Checkbox 的 hover 一律沿用既有跨元件的 6% 白色疊加技法（opacity.hover-overlay，Tabs／Menu／List-item／Breadcrumb／Accordion 已用過的既有作法），不是本批新增的視覺決定；Text input／Textarea 則不加 hover（既有的 Search field／Number input 欄位同樣沒有 hover 處理，維持一致）。
